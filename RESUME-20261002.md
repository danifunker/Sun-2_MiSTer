1. **DONE 2026-10-03: the mouse.** On the board the whole path worked all
   along: with a virtual USB mouse (`tools/mister_keys.py` `{M dx dy}`, `{ML}`
   `{MR+}` ...; `{PIPE}` types a `|`), `od -x /dev/mouse` showed every
   packet and SunView's pointer moved.  What was wrong was pacing: the bridge
   queued a whole packet per MiSTer event in a 64-byte FIFO and dropped new
   ones when full, while Main sends up to ~66 events/s and 1200 baud carries

2. **DONE 2026-10-03: the OSD auto-mount, and the timing that blocked it.**
   `Sun-2.sv` CONF_STR disk entry is `SC0`: Main saves the disk last chosen
   (`config/Sun-2.s0`) and remounts it at core start, and the PROM auto-boots
   it -- verified on the board by loading the bare `.rbf` with no MGL.  The
   one-line change re-placed the design and cpu_clk missed setup (-0.024 ns at
   SEED 7, -0.276 at seed 2).  Root cause, not a seed: RD68011's shifter
   (`count % w`, `count % (w+1)`) synthesised two general dividers on the
   critical path (ucode ROM -> shift-count decode -> divider -> barrel ->
   `u_biu.d_o`, a half-period R->F path).  `rtl/patched/rd68011/
   rd68011_shifter.sv` replaces both with exact small logic; `files.qip` builds
   it instead of the vendored copy (left untouched; see `rtl/patched/README.md`).
   `tb/verilator/tb_shifter_equiv` checks it against upstream for every control
   input (139,264 checks; two mutations caught).  Result at SEED 7: cpu_clk
   setup +1.010 ns (was +0.272 at best), every clock passes; worst remaining is
   MiSTer's `ascal` scaler on the HDMI clock, +0.045 ns (framework, not ours).
   Board image: `_Unstable/Sun-2_20261003.rbf` (md5 7e573061...).  Upstream

4. **DONE 2026-10-03: the clock, from MiSTer's.**  `rtl/sun2_mister_tod.sv`
   takes hps_io's `RTC` (MiSTer local time, BCD, sent at core load and every
   minute; only the first update is used, as a battery clock would) and loads
   the MM58167 (`mm58167.v` gained `LD`/`LD_TIME`, a load during por_reset is
   kept and applied after; wired Sun-2.sv -> top_fpga -> sun2_vme_scsi; the
   MultiBus TOD in sun2_fpga ties it off).  Not TIMESTAMP: for cores Main
   does not know are UNIX (`rtc_is_utc()` is NeXT only) it is UTC less the
   *standard* offset, an hour out under DST -- measured on the board.
   **What the chip holds is SunOS's encoding, not a date** (tod.c, confirmed
   in 4.0.3's own todget/inittodr disassembly): `t % 31536000` as a no-leap
   month/day/h/m/s, weekday = day % 7 + 1; todget() picks the t nearest the
   root fs_time (+-half a year).  So the core cannot set the year -- the disk
   carries it -- only the day-of-year and time: MiSTer's local time less 36
   years (a multiple of 4, so dates match exactly for a disk in 1990, the
   user's choice of a period year short of Y2K).  Per disk, once: zone to GMT
   (`ln /usr/share/lib/zoneinfo/GMT .../localtime`, a hard link as suninstall
   makes it) and `date 9010031400.00`, then touch/rm/sync so fs_time is
   written in 1990 (README "The clock").  Done on sd0-1g.img; the user's
   sd0.img is still in 1988 with US/Eastern.  Board: cold start read `Wed Oct
   3 13:39:03 GMT 1990` with MiSTer at 13:39:03 EDT, clean fsck, no warning.
   `_Unstable/Sun-2_20261003d.rbf` (md5 9071d9a3...), cpu_clk +1.683 ns.
   Tests: `tb_mister_tod` (70: todset() model, todget() round trip, the civil
   date, edges 2006/2069, out-of-range years, once only, a load in reset),
   `mutate_tod.sh` 10 of 10.  Moving a disk's clock back makes fsck report
   `SUMMARY INFORMATION BAD` once (cg_time in the future; on /usr also

6. **Machine identity / Ethernet address.** The ID PROM (`rtl/sun2-common/idprom.v`)

   no such command). Plan agreed in chat: a Main_MiSTer hook (core name "Sun-2") reads
   eth0's MAC (`SIOCGIFHWADDR`, as `support/mac/mac_eth*.cpp` does for MacQuadra800,

   holds reset until the PROM arrives); the core folds them into ETH3..5 and
   recomputes the checksum (XOR of bytes 0..14 = byte 15). Interim option: optional

   A Main_MiSTer fork/PR is the user's call — ask.

- `rtl/vendor/*` are unmodified upstream copies: change upstream, re-copy.
- Board screenshots (`echo screenshot > /dev/MiSTer_cmd`) do not show the OSD;
  OSD changes are blind — verify by effect (e.g. the `.qic` fd position in
  `/proc/$(pidof MiSTer)/fdinfo`).
- Keyboard: L1-A = hold Right Alt+F1, press A. curses screens drop fast keys.
- SunOS facts: the Sun-2 disk ceiling is 1 GiB (21-bit six-byte CDBs); 4.0.3 tapes
  are upgrade-only; the 4.0 tape is the full install.
